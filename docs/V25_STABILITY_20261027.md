# V25 天氣空白、切頁閃退與 Dock 黏合修復

修復三項回報：天氣下滑空白，切換頁面／設定時閃退，以及 Dock 尾端尺寸不一致。

## 改動

- 玻璃取樣先計算來源、卡片與捲動視窗的交集，僅配置可見大小的離屏區域，記錄與輸出兩端均裁切，卡片另有圓角裁切。非法、巨大或離屏區域改用一般材質。
- 以 CompositionLocal 擷取祖先集合阻止自我取樣，取代無法涵蓋延後 RenderNode 錄製的暫時旗標。獨立場景供頁面使用，頁面來源僅供外側 Dock。軟體更新頁也採用獨立背景。
- 前景固定經正常 drawContent 顯示；Java 層取樣例外不會隱藏頁面。這無法攔截所有原生 GPU 崩潰。
- Dock 兩個主體共用完整寬高，只有位置與中間頸部改變。360 dp、四分頁、68 dp 高的既有 Dock 中，兩個主體均為 79 × 56 dp。這是本 App 幾何，並非宣稱 Apple 官方像素。
- 天氣捲動狀態提升到 Pager 外，Dock 使用 Pager 目標頁。新增本機 Java 及 ApplicationExitInfo 異常紀錄，不自動上傳。

## 驗證與交付

BackdropSamplingTest 與 DockLiquidGeometryTest 共新增 10 個單元測試。RenderingRegressionTest 包含三個裝置測試：前景標記不被蓋掉，延後錄製的子層不能取樣祖先，以及固定測試天氣的捲動與反覆進出外觀設定。測試使用手動動畫時鐘，保留動態效果。

GitHub 候選建置會在 API 35 硬體加速模擬器執行畫面測試；失敗停止候選簽章與輸出。報告、logcat 與測試畫面放在 thinn-khi-ui-regression artifact。UI 測試與候選打包使用不同 runner，後者透過 needs 等待前者通過，避免測試輸出與候選版本／簽章互相污染。測試腳本拒絕實體裝置，避免測試資料寫入個人 App。

精簡包只含 22 個修改，UPLOAD.sh 取得 GitHub 完整 main 後三方套用、執行全部 Python 回歸檢查，再啟動候選流程。保留既有簽章、版本與正式發行限制，不強制推送、不自動發布 OTA、不刪除鬧鐘或設定。

原手機崩潰堆疊尚未取得；所有閃退的原因及修復是否完整仍需原裝置驗證。逐項測試結果見包內 VERIFY_REPORT.md，不能把已編譯的 UI 測試視為已執行通過。

## #292 建置逾時修正

2026-10-27 的 run 40439568750（commit 3d3dc25）已成功啟動模擬器並編譯 App／AndroidTest。裝置紀錄確認前景裁切與祖先循環取樣兩項測試通過。第三項 weatherScrollAndRepeatedSettingsNavigationKeepVisibleText 自 10:43:52（台北時間）啟動後沒有完成，11:38:16 達到工作 60 分鐘上限而取消；該次沒有產出候選 APK。

第三項測試在手動時鐘暫停時呼叫 performScrollTo。Compose 1.8.0 的實作反覆發送捲動、同步與讀取座標，並未替手動時鐘推進動畫，存在無限等待。改以最多 8 次 ScrollBy、逐次推進 650 ms 並驗證位移；文字仍須實際繪出、四輪進出設定仍須完成。舊紀錄沒有當時的執行緒堆疊，因此這是由原始碼辨識的等待缺陷，不應將它描述為已取得該次停住位置的堆疊證明。

每項裝置測試限制 120 秒，Espresso 同步限制 30 秒；主機 connected 測試限制 480 秒，失敗或逾時保留非零狀態與 logcat、進度、畫面、Activity／繪圖狀態。只接受三項完整且無失敗／略過的 JUnit 裝置結果。先編譯 fixture APK 再啟動模擬器，降低同時編譯與軟體 GPU 繪製的資源競爭。

Pull request 僅執行讀取權限的畫面驗證；正式候選建置仍須手動啟動，且保留原有簽章、版本、來源及發行限制。
