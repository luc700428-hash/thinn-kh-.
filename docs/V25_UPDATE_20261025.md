## 上傳與 APK

從更新包根目錄執行 `bash UPLOAD.sh`。腳本會檢查每個檔案的 SHA-256，在獨立 Git 目錄套用可合併的補丁，保留 main 的其他修改；遇到同段程式衝突即停止，不使用強制推送。重跑可辨識已套用內容與既有建置。

上傳後自動執行原 `build-apk.yml` 的 APK 建置，`publish_release=false`。原簽章憑證存在時，Actions 產出同簽章候選 APK；未設定原憑證時只能產出測試 APK，不能將它當成可覆蓋正式版的更新。必要 Secrets：APK_KEYSTORE_BASE64、APK_KEYSTORE_PASSWORD、APK_KEY_PASSWORD、APK_KEY_ALIAS。此包不含私鑰、帳號 token 或電腦 SDK。

正式發布仍須原簽章、版本遞增、原版覆蓋安裝、資料保留與實機驗收。`next_release_gate.json` 未被假設為全部已驗證；只有實際補齊驗收記錄後，原 workflow 的正式發布開關才可通過 gate。這項保護不會建立需要使用者合併的 PR。

## 驗證範圍與限制

完整命令、結果與日誌在更新包的 VERIFY_REPORT.md / checks/。本地 Debug 簽章及 unsigned Release 只用於編譯檢查；正式簽章須由既有 GitHub Secrets 產生。

尚未取得使用者手機的對照截圖與錄影，未執行 Samsung／Pixel 的鎖屏響鈴、長時間背景下載、200% 字級、TalkBack、耗電與幀率測量，也未在已安裝正式版上執行同簽章覆蓋安裝。這些不能以編譯或 Python 檢查取代。

iOS 是幾何、材質和交互參考；本工程使用 Android 系統與可合法分發的字體／圖示。未宣稱使用 Apple 私有框架或已達裝置上的 100% 像素一致。既有 Weather Lab 本機 CSV 匯入、來源限制及其真實狀態提示保留，未偽造新的即時資料服務。

## 復原

上傳腳本的變更是一筆獨立提交。若功能驗收失敗，對該提交執行 git revert，再建置一個更高 versionCode、相同簽章的修正版；不以解除安裝或清除 App 資料作為一般回復方式。GitHub main 在上傳期間前進、簽章不同或來源驗證不符時，流程應停止並保留紀錄。
