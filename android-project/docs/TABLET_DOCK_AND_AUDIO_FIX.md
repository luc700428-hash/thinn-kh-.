# 平板四邊 Dock 與天氣音效修正

設定路徑：**設定 → 平板 Dock 位置**。預設右側，可選底部、左側及上方；偏好會保存，並立即套用。

## 工作區

平板四個主頁直接使用常駐 Dock，移除原有選單與側邊主頁列表。右／左為直向，上／下為橫向，圖示與文字保持正向。頁面以 Dock 的尺寸預留內容區，靜止時不會把文字或操作按鈕壓在 Dock 下方。

當目前內容區太窄，或高度不足以放下四個可用的直向觸控目標時，暫用底部 Dock。使用者保存的偏好不會被改寫；視窗變大後恢復原位置。書本、桌面與不對稱鉸鏈仍使用安全的一側；另一側可顯示天氣概覽。手機及窄外螢幕維持底部導覽。

所有方向共用 NextReorderableToolDock、AppleLiquidDockPaint 與固定的四個主頁順序。直向採上下拖動，橫向採左右拖動；放開才提交一次換頁，取消手勢回復目前頁。玻璃選取保持等大水滴、黏著尾部、彩色邊緣光、按壓與回彈，不旋轉文字。

位置切換採 400 ms 線性移動與平順的內容區調整；改變方向時以短暫淡化銜接直、橫形態。減少動態效果時直接定位。旋轉、視窗尺寸或鉸鏈改變時重新計算安全區，並限制過場幾何範圍，避免負邊距及跨鉸鏈的瞬間錯位。

鍵盤彈出時以實際剩餘高度安排 Dock，必要時暫用底部，不會因鍵盤變矮而切回手機導覽模式。

工作區內容保持固定的 composition 根節點。調整 Dock 不重新建立整個 pager，保留輸入、滑桿、頁面及正在播放的環境音。

## 音效根因

原本 NextLoopTrack.open 在寫入 PCM 前要求 AudioTrack 已是 STATE_INITIALIZED。Android 的 MODE_STATIC 在尚未寫入資料時，合法狀態是 STATE_NO_STATIC_DATA，因此原判斷會把正常的播放器直接釋放，最後顯示「目前音效無法播放」。

修正流程為：確認分配未失敗 → 寫入完整 PCM → 確認可播放狀態 → 設定循環。保留載入錯誤、媒體音量為零、音訊焦點占用及 App 離開前景的不同提示。

「試聽」新增明確的重試序號。每次重新試聽可建立新的播放器，避免重複使用失敗或失效的音軌；普通音量調整仍沿用目前音軌。與環境音共用此播放器的天氣鬧鐘也使用修正後的初始化流程。

依據：[Android AudioTrack：STATE_NO_STATIC_DATA、getState、write、setLoopPoints](https://developer.android.com/reference/android/media/AudioTrack)；[Android 音訊焦點](https://developer.android.com/media/optimize/audio-focus)。查閱日期 2026-10-31。

## 驗證

- 原生版面：四邊、橫直向、短視窗、明暗主題與 100／150% 字體；Dock 與內容區不重疊，選取清楚，輸入與滑桿狀態保留。
- 原生手勢：上下／左右拖動、僅提交一次、取消不換頁、位置移動過場。
- 實際設定頁：四個位置互斥選取、保存偏好並移動目前 Dock。
- 音訊：平台初始狀態、所有天氣 PCM 音檔、鬧鐘使用類型、前景播放、靜音、暫停／恢復、失敗重試，以及完整 App 設定的試聽／停止／再次試聽。

測試使用固定資料與本機回應，不傳送測試位置至外部氣象服務。原生測試不能取代實機對音量、GPU 光效、桌面啟動器及折疊感測器的驗收；沒有宣稱強制突破硬體刷新率或 Android 音訊焦點限制。動效測試手動推進 vsync，避免測試框架自動把動畫推到結束；鍵盤測試注入 IME insets。實際通過數量及建置紀錄以更新包 validation/ 為準。
