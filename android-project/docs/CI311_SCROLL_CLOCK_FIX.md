# 第 311 次 OTA 建置：工具頁手動時鐘捲動修正

基底：`0f46a8c5c3e4e6fc6ca80fe6fdb701ab699c2ebe`。
原始失敗：https://github.com/luc700428-hash/thinn-kh-./actions/runs/40690649206 。

## 問題與證據

第 311 次建置已成功編譯 App 與介面測試 APK。模擬器執行的 8 項介面測試有 7 項通過；唯一失敗為 `allToolsGroupsAndFilteredLastGroupRenderInBothAppearances`，在 120,000 毫秒後逾時，堆疊停在 `performScrollTo`（原始測試第 219 行）。這份紀錄未顯示該次失敗是 App 閃退。

測試的 `prepare()` 將 `mainClock.autoAdvance` 設為 `false`。工具分類增加內容後，最後的分類必須捲動才能看見；`performScrollTo` 反覆等待非同步捲動，期間卻沒有推進已暫停的動畫時鐘，因此無法完成。原始測試的搜尋結果辨識、文字對比度、滑桿與 Dock 測試並未因而被移除。

## 修正

工具頁改用與已通過的天氣頁相同的明確捲動方式：量測目標與捲動容器、限制合法位移範圍、呼叫 `ScrollBy`、推進 650 毫秒的測試時鐘，再檢查實際捲動位置確實改變。目標到達時仍必須通過 `assertIsDisplayed`，並保留最多 8 次的明確失敗條件。工具搜尋框也使用同一個方法捲回畫面內。

原有天氣頁 helper 改為呼叫共用 helper；位移計算、時鐘步進與進度斷言沿用既有實作。新增紀錄會指出明亮／深色外觀、分類、捲動前位置與要求位移，方便下一次 CI 直接查出卡住的位置。

仍保留全部 8 項測試、每項 120 秒上限，以及 CI 的嚴格結果檢查和建置相依關係。沒有調高逾時、略過測試或修改 App 功能程式、依賴與簽章流程。

## 驗證範圍

更新包的 `validation/` 收錄原始 CI 失敗證據與本機驗證結果，兩者分開標示。本機重播使用實際修正後的測試方法及 helper、相同 Compose UI 測試規則與暫停動畫時鐘，在 Robolectric 原生繪製 API 35、360 × 640 dp 視窗執行工具分類捲動、搜尋、開關世界時鐘與清除搜尋，明亮與深色各一輪。Robolectric 設定與額外測試依賴只加入隔離驗證目錄，不寫入專案。

這是本機 Android 執行環境驗證，並非手機或 Android 模擬器重跑。新版本仍須通過 GitHub Actions 的全部 8 項介面測試，才可繼續產生候選 APK。此更新包本身不含正式簽章 OTA，也不宣稱全部功能已通過真機驗收。
