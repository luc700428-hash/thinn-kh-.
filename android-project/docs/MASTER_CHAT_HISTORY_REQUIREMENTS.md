## 三、現況的硬性事實（由工程檔檢查）

- 候選原始碼：`native/android-project`，包含 Android Kotlin/Compose、地震及天氣 backend、OTA manifest 產生器。
- `catalog_v2.json` 實際包含 **132 筆候選地標資料**及 **20 個島嶼地域**；這不是「所有島嶼都已完成建模」。
- 其中 **17 筆 `original_prototype` GLB 原型**，其餘 **115 筆尚無可播放的專屬原型**。
- `WeatherHomeScreen.kt` 的 `LandmarkCanvas` 實際以 `Image(bitmap=...)` 呈現 **PNG 圖像**，不是 Filament 即時 GLB 渲染。
- `native/.github/workflows/build-apk.yml` 候選版會編譯追蹤的 `android-project/`；GitHub main 的舊流程仍需成功部署替換，否則仍可能使用固定 V22 ZIP。
- 靜態/政策本地測試：Python 32/32、Node 7/7 通過；**無法因此認定完整 Android UI 可編譯或真機所有功能可用**。
- 舊 ZIP 正式發布或 HTML 原型**不構成**實機更新；必須以 GitHub commit、workflow、APK hash、原簽章升級及裝置截圖查驗。

## 四、不可跳過的最終驗收門檻

1. 全數保留所有要求並以 ID 明確追蹤，新增需求不得覆蓋舊需求。
2. GitHub main 有實際更新的 `android-project/`，建置工作流程不再抽取舊 ZIP。
3. GitHub Actions 完整單元測試、Kotlin/Compose compile、assembleRelease 通過，出現可下載的 signed APK。
4. 同一 release 有 `thinn-khi.apk`、`thinn-khi.apk.sha256`、`ota.json`，校驗碼比對一致，原簽章覆蓋安裝成功。
5. 在真實 Android 手機依首次啟動→授權→天氣→地震→工具→新增/編輯/提醒→設定→系統更新→Widget 逐頁操作，保留截圖與問題紀錄。
6. 全 App 所有重要資訊不用額外點擊便能看見；對比度、動態天氣背景、大字體/螢幕閱讀器/降低動效/低階效能測試通過。
7. 微縮城市定位核對實際在地島嶼，臺灣22縣市各有多個**可辨識建模地標**，無假小屋、無以 PNG 冒充 3D 的情況。
8. 對 EEW 真實資料、來源/模擬區分、推播/聲音、衛星/雷達資料授權與服務逐項實測，不得宣稱未完成品已能使用。
9. 正式 OTA 發布後確認 App 顯示的介面與 GitHub commit 完全相符，且朋友可免 GitHub 登入更新。

**P001** `Heading 1` — 執行摘要

**P002** `First Paragraph` — 本研究全面盤點並整合 thinn-khì App 的重設需求：優先以用戶安全與即時性為首要目標，包括強化地震速報推播與警報界面；符合 iOS 27「Liquid Glass」與最新人機介面規範，重建 UI 視覺與動畫；整合智慧生活穿搭功能與免費開源 AI，以提供具體生活建議；改善降雨雲圖資料來源與顯示，提供真實雷達/衛星雨量圖；以及確保上架品質（無障礙、響應式、完整測試與 OTA 發布流程）。本規格將每項功能拆解為可實作的技術細節，包括配色、字級、圓角、動效參數、後端 API 等具體數值與範例程式碼，同時列出優先順序與風險。

**P003** `Heading 2` — 明確目標與優先順序

**P004** `Compact` — 安全警報：地震速報必須強制彈出並有聲音、語音提示，以確保用戶注意；主動使用 FCM 高優先推播，必要時啟用 Android 全螢幕通知（Full-Screen Intent），但須考慮 Android 14+ 的限制【47†L99-L108】。

**D001** — 執行摘要

**D002** — 此研究旨在將 thinn-khì App 的「微縮城市」功能重建為依使用者定位，展現各縣市具代表性的微型地標。我們將為台灣22縣市（含離島與小島）以及若干國際知名地標建立真實感的 3D 模型，並實作無縫動畫切換、定位優先邏輯和完善的資產管理流程。本報告涵蓋目標與成功標準、地標清單與座標、3D 資產製作及工具鏈建議、UX/動畫規範、定位與快取策略、可及性與效能、法律隱私考量，以及詳細的實施路線圖、里程碑與工作量估算。

**D003** — 目標與成功準則

**D004** — 定位感知展示：App 開啟時，優先顯示使用者所屬縣市的地標，並標註「縣市、地標名稱」格式。例如「高雄、夢時代」。

**D005** — 多縣市地標涵蓋：涵蓋台灣本島22個行政區及離島（澎湖、金門、馬祖），並納入指定國際地標。每地區可包含多個地標，具代表性與觀光性。

**D006** — 高品質 3D 模型：依地標重要性與可用資源定義「建模等級」（高/中/低），採用 PBR 材質與適當多邊形數。中高重要度地標採高品質建模，中度地標使用中等細節，低度地標或地理標記採簡易模型。

**D007** — 無縫動態過場：實現 App 開啟或切換地標時的流暢動畫過場。相機路徑平滑過渡，不突兀跳動。中途採用佔位畫面或進度條避免白屏。

**D008** — 優化效能與可及性：在中階 Android 設備保持流暢（30-60fps），確保 UI 元件可及性（大字體、TalkBack 支援）、震動觸感與互動回饋連貫。

**D009** — 自動化與擴充性：建立 3D 資產管線與 CI/CD 部署流程，使新版地標或動作可自動推送到 GitHub 進行編譯部署。版本資訊改為公開 JSON 檔，避免使用 GitHub API 查詢限制。

**D011** — 以下以表格列出台灣本島22行政區、離島及示例國外地標。地標以具代表性或觀光性為主，每項附 GPS 座標、建模等級、資料來源／授權、優先度。資料來源優先官方/開放資料、Wikimedia Commons、政府機構、觀光局或 OpenStreetMap 等。

**D013** — 3D 資產管線建議

**D014** — 檔案格式：統一採用 glTF 2.0（擴充名 .gltf 或 .glb），支援 PBR 材質、動畫、層級結構。相比古老的 OBJ 格式，glTF 支援貼圖、法線、金屬度/粗糙度材質等【59†L238-L246】，亦易與 Filament 等渲染引擎整合。

**D015** — PBR 材質：使用金屬度/粗糙度（金屬-粗糙）PBR 工作流程，配合 HDR 環境光遮蔽貼圖，以求真實外觀。所有材質貼圖以 sRGB (色彩) 或 Linear（物理量）格式儲存，貼圖尺寸視物件大小與遠近適度選擇（一般 512×512 至 2048×2048）。

**D016** — 多邊形預算：中階行動裝置目標 30fps。高等級地標模型宜控制在20,000–50,000 三角形以內；中等級約5,000–20,000 三角形；低等級 <5,000 三角形。可分多 LOD 級別：遠距時載入低細節，中景載入中等級，近景/展示時載高細節。如微縮城市圖中地標為縮尺模型，可比實體建築少量多邊形。

**D017** — 法線映射：對於材質需細節的部分（例如建築雕刻、磚石紋理），使用法線貼圖提升視覺細節，避免增加過多幾何。

**D018** — 資產工作流程：建議使用 Blender 等工具建模（自由且腳本化），再匯出 glTF (可使用 Blender glTF 插件)。或使用遊戲引擎（Unity/Unreal）亦可，但需支援匯出 glTF。為保證跨平台，使用 Filament 或類似支援 glTF 的渲染引擎（Android 原生支援 Filament、Sceneform 開源版）【59†L238-L246】。

**D019** — 自動化 CI/CD：在 GitHub Actions 上設置 3D 資產管理流水線。將原始 Blender/素材檔放在 assets-src/，利用 CI 自動匯出 .gltf/.glb 到 assets/ 資料夾。可使用如 gltf-pipeline 工具優化壓縮模型。每次資料夾有更新時，Actions 自動重新建置並部署到 GitHub Pages 或物件儲存。所有素材版本皆可控於 Git 版控中。
