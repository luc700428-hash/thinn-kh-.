# thinn-khì 10.6.0 — 修正與 OTA 發布指南

此為 **Android 原始碼測試版**，不是已編譯 APK。沿用既有 `io.atmos.weather` 套件名稱。

## 這次 12 項改動

1. App 內 `brand_mark.png` 與所有 Android 密度圖示均改用同一套 `V10.5-original-icon.png` 來源生成。若手機桌面暫存舊圖示，可能需要重新啟動桌面啟動器。
2. 逐時預報改用 **單一 ScrollState**：所有小時的曲線、天氣圖示、風速、時間文字，與上方選取資訊都跟隨同一次水平滑動。曲線不再額外攔截手勢。
3. 空氣品質採可選 **WeatherAPI**；需要使用者自己的 API Key。PM2.5、PM10 與能見度來自 `current.json`，不把 US EPA 指數當作台灣 AQI。
4. 平時若官方 RSS 成功查詢但沒有所在地匹配公告，只顯示「目前未找到所在地相關的最新特報公告」；讀取失敗則明確顯示暫時無法確認。警報卡片仍依據已匹配公告顯示。此系統無法代替官方完整有效警報服務。
5. 智慧生活建議擴充了未來六小時、降雨機率、體感、濕度、風速、UV、日落、溫差、能見度、PM2.5 的多因素規則。非雲端 LLM，所有提醒由現有預報數值產生，不會生成虛構警報。
6. 新使用者雨滴觸覺預設開啟。
7. 新使用者雷雨閃電觸覺預設開啟。
8. 新使用者「省電模式降低震動」預設關閉。已有使用者偏好不覆蓋。
9. 移除台灣環境部 AQI 查詢、金鑰設定與對應客戶端。
10. 能見度與污染物濃度同樣由 WeatherAPI 回傳（無金鑰時顯示不可用，不會假造數字）。
11. App 新增設定頁「檢查更新、下載並安裝」。檢查 GitHub Releases 的 latest，驗證 SHA-256 和套件名稱，系統確認後安裝；必須使用相同簽署金鑰。**不是靜默 OTA**。
12. 首頁溫度數字置中，度數符號 `°` 放在數字右上，不影響數字置中。

## 每次測試版編譯

1. 把 `thinn-khi_Android_Source_V10_6.zip` 上傳至 GitHub repository 根目錄，保持檔名不變。
2. 將 `thinn-khi-V10_6-build-apk.yml` 內容貼到 `.github/workflows/build-apk.yml`，提交至 `main`。
3. 到 Actions，選最新 `Build thinn-khi V10.6 APK`。成功後在 Artifacts 取得測試 APK；失敗下載 `thinn-khi-V10_6-errors` 並提供紀錄。

## 正式 OTA 發布（只需首次設置金鑰，後續繼續用同一把）

**重要：既有 `app-debug.apk` 為 Debug 簽署**，通常不能被正式 release 簽署的 APK 直接覆蓋。首次轉正式版時可能必須先備份資料再解除安裝舊測試版；之後正式版更新**一律使用同一把私密簽署金鑰**，才能不解除安裝直接升級。

1. 用 Android Studio 或 `keytool` 在自己安全的電腦產生 **一把** `thinn-khi-release.jks`，請自行妥善備份，絕對不要上傳 GitHub 公開專案。示範：`keytool -genkeypair -v -keystore thinn-khi-release.jks -alias thinn -keyalg RSA -keysize 3072 -validity 10000`
2. GitHub repository 的 Settings → Secrets and variables → Actions 設定四個 Secrets：`APK_KEYSTORE_BASE64`（將 JKS 檔 base64 編碼後的字串）、`APK_KEYSTORE_PASSWORD`、`APK_KEY_PASSWORD`、`APK_KEY_ALIAS`。
3. 將 `thinn-khi-V10_6-release-apk.yml` 放至 GitHub 的 `.github/workflows/release-apk.yml`。
4. 確認專案 `app/build.gradle.kts` 的 `versionCode` 比已發行的版本大，`versionName` 和要發布的 tag 一致。此版是 `versionCode=19`、`versionName=10.6.0`。後續每一版皆需遞增 versionCode。
5. GitHub Actions 中選擇 `Publish signed thinn-khi OTA release` → Run workflow，輸入 `v10.6.0`。工作流程會建置 Release、zipalign、使用 Secrets 簽署、apksigner 驗證並發布 GitHub Release（包含 `thinn-khi.apk` 和 SHA256）。
6. App 內「設定 → App 更新 → 檢查更新」，如比安裝版本新，按「下載並安裝」，Android 系統會顯示安裝確認。若沒有該安裝來源權限，系統會要求先允許。

這個設計從 `https://api.github.com/repos/luc700428-hash/thinn-kh-./releases/latest` 取得版本。**若實際 repository 名稱不同**，請修改 `AppUpdater.kt` 的 `api` 常數。

### 安全與平台限制

- SHA-256 是檔案完整性檢查；Android 最終仍會驗證 APK 簽署與既有安裝版本的一致性。
- Android 不允許一般 App 無提示靜默安裝任意 APK；由系統安裝器要求使用者確認。
- 放到 Google Play 上架時應改用 Play 的 In-App Updates，並遵守 `REQUEST_INSTALL_PACKAGES` 政策。
- 「GitHub Releases latest」只識別正式公開發行，不檢查 Actions artifacts 或 draft release。
- WeatherAPI 有配額、API Key 與授權要求；用戶可自行到 WeatherAPI 申請，未設定就不顯示新來源的數據。
- 本地執行僅通過局部 Kotlin 編譯、XML、YAML、ZIP 檢查；**完整 Android 編譯與安裝、OTA 測試仍需要 GitHub Actions／Android 實機**。
